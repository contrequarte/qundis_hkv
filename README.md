# qundis_hkv (converting HKV XML files to csv)
Due to the regulations in Germany, starting latest with January 2027, he legislator stipulates in section 6a of the Heating Costs Ordinance ("Heizkostenverordnung") that the building owner must provide users with subannual (monthly) heating and (if applicable) hot water consumption information (in German language named UVI "unterjährige Verbrauchsinformation"). Each radiator has been equipped with a metering device, which collects the consumption data and sends a datagram containing these data to a gateway which sends the data collected to a company (often the manufacturer of the metering devices). At the 1st of a month, I receive an email with am zip atchive attached. The archive contains a XML document containing the consumption values of each metering device for the last 12 months. Among other it also contains the consumption as of the 1st of the current month. I'm using a provider, which can handle all costs and earnings coming up with renting a house or a flat and additinally via a portal solution provides the "UVI" to the tenants.
During my testing of this solution, I've found out, that the providers software is getting confused by the values for the current month additionally contained in the xml document. There's no big difference between the values of the last day of a month and the values od the first day of the next month (except for January due to rest at endof year), but nevertheless to me, being a little narrow minded, it wasn't OK.
Therefore I've been playing around with Python and the XML documents to processes the files correctly and create a simple csv file containing only last months data. Having done this, I added some functionality to pick the email from my google account process the file and send the csv file to the provider who supports simple csv files too. To get rid of a manual task to start the the Python script each time, when I've received a new file, I've wrapped the entire thing in a docker container. This (small, low weighted) container checks each day, if a new email with data attached has arrived and if yes, starts the processing.
